# SKMTC C# language layer

This skill covers the **target-language** side of generator authoring:
what the emitted C# looks like and which package owns each piece. The
boundary rule, worth internalizing first:

> **The authoring language is always TypeScript/Deno; only the target
> language varies.** Rules about how generator *source* is written
> (`as` casts, `switch`+`never`, `Deno.env`, Valibot enrichments) live
> in `skmtc-generator`. This skill covers how the generator's *output*
> is shaped — files, usings, definitions, identifiers, naming — for
> generators whose target is C#.

> **Template contract.** This skill keeps the seven section headings of
> `skmtc-lang-typescript` (the template) and replaces the answers — the
> third instantiation after `skmtc-lang-kotlin`. The Kotlin boundary
> rule carries over verbatim: **`lang-csharp` is grammar, `gen-csharp`
> is OpenAPI policy.** `System.Text.Json` is never named inside
> `lang-csharp` — the lang package renders any attribute it is handed;
> *which* attribute to emit is generator policy. Arc spec (single
> document): `notes/lang/31-csharp-kickoff.md`.

## 1. Package surface

`@skmtc/lang-csharp` exports:

| Export | What it is |
|---|---|
| `csharp` | The `Lang` object. Three neutral factories the engine's **Drivers** call, reading it ephemerally off the projection class's inherited static (`projection.lang`): `createFile`, `toDefinition`, `toImport`. Generators never call it. |
| `CsSnippet` | The snippet base — where C# enters the DSL class hierarchy. Carries the static `lang`; its `register` / `defineAndRegister` methods are typed by the concise vocabulary. Registering snippets are **keyless** (`generatorKey` is optional attribution input) |
| `toModelProjectionBase` | The model projection-base veneer over core's factory — pre-binds `base: CsSnippet` and adds own-file `register(args)` + explicit cross-file `registerInto(destinationPath, args)` (+ `CsModelProjectionBaseConfig`). No operation veneer exists yet — veneers are demand-driven (the Kotlin precedent); the first operation generator arrives at CS-C |
| `register` / `defineAndRegister` | The register **functions** — convert the concise form, ensure the destination `CsFile`, hand pure data to the neutral `context.register`. Transforms (closures with no class) import `defineAndRegister` directly |
| `CsRegisterArgs` / `CsDefineAndRegisterArgs` | The concise register vocabulary (`imports` / `definitions`) — **deliberately NO `reExports` field**: C# has no re-exports, so registering one is a compile-time error, not a runtime no-op |
| `CsFile` | `CodeFileBase` subclass — a C# output file: the `// <auto-generated/>` + `#nullable enable` header pair (compiler-mandated — see §6), sorted namespace-collapsed `using` section, file-scoped `namespace X.Y;` **derived from its own path**, same-namespace using suppression |
| `CsImport` | `ImportBase` subclass — symbol-level specifiers at the register boundary, namespace-level rendering (`using Ns;`, one per distinct namespace), `using Alias = Ns.Type;` alias form, mergeKey/merge dedup, `@/`-path → namespace resolution at render |
| `CsDefinition` | `DefinitionBase` subclass — the declaration shells, exhaustive over the kind vocabulary (throws outside it); visibility from `exported` — BOTH states render a keyword (`public ` / `internal `); reads class-level attributes off the value via the `CsAttributed` protocol and the XML-doc summary via `CsDocumented` |
| `CsPropertyList` / `CsPropertyArgs` | Nominal-record property members: attribute lines above each property, `public` + optional `required` + type + optional `?` + name + `{ get; init; }`, blank-line-joined — statement-shaped, the construct geometry D3 chose nominal records to get |
| `CsAttribute` | Generic attribute rendering: `[Name]` / `[Name(arg, …)]` — args pre-quoted by the caller |
| `CsAttributed` / `isCsAttributed` | The protocol (`{ attributes: CsAttribute[] }`) by which a Definition's VALUE supplies class-level attributes to `CsDefinition` (the neutral `Lang.toDefinition` has no attributes slot); cast-free type guard |
| `CsDocumented` / `isCsDocumented` | The protocol (`{ description?: string }`) on a Definition's VALUE supplying the XML-doc `<summary>` block `CsDefinition` renders above the attributes (an explicit constructor `description` wins). The lang renders (and XML-escapes) the block; WHAT the text is is generator policy. Gotcha (spec 28): the Driver wraps the PROJECTION, so value protocols must be MIRRORED as getters on the projection |
| `CsBased` / `isCsBased` | The protocol (`{ baseTypes: Stringable[] }`) for the ` : Animal` base-type clause, rendered for the record-family kinds (between the name and the body, or before the `;` on the bodyless collapse); bare names, no import behavior (same-namespace suppression makes them correct); mirror it on the projection — the Driver wraps the projection, not the value |
| `CsImportNameArg` | The concise import-name shape (`'Name'`, `{ name, alias }`) accepted by `register({ imports })` |
| `createRecord` / `createAbstractRecord` / `createEnum` | The identifier factories — build neutral `Identifier`s with this language's `kind` vocabulary |
| `CsEntityKind` / `toCsKeyword` | The three-kind vocabulary and its declaration-keyword mapping; throws outside the vocabulary. The D3/D14 modifiers ride the mapping: `'record'` → `sealed partial record`, `'abstract-record'` → `abstract partial record` |
| `sanitizePropertyName` | C#-specific name sanitization (§5) |
| `toNamespaceName` | `@/`-path → dotted-namespace derivation + segment validation (C#'s `validateDestinationPath`) |
| `csHardKeywords` / `isCsIdentifierName` | The pinned reserved-keyword set (77) and the plain-identifier syntax check |
| `toCsEnumMemberName` / `toCsEnumMemberNames` | Enum member naming: PascalCase per wire value, plus the FULL-PRODUCED-SET dedup (the note-30 `A_B_2` lesson) with a `reserved` pre-seed that dodges CS0542 for enum members |
| `withDescription` | XML-doc `<summary>` helper — XML escaping (`&` / `<` / `>`) lives HERE, in the lang (note-30 lesson 3) |
| `langId` | `'csharp'` |
| `fileExtensions` | `['.cs']` |

### Wiring — the import graph declares the language

```ts
// gen-x/src/base.ts — the language enters HERE, through the import
import { toModelProjectionBase, createRecord } from '@skmtc/lang-csharp'

export const MyBase = toModelProjectionBase({
  id: denoJson.name,
  toIdentifier({ refName }) { return createRecord(name) },
  toExportPath({ refName }) { /* @/<namespace dirs>/<Name>.generated.cs */ }
})
```

There is no `lang` config field anywhere; entries are pure pipeline
config. Generators never construct `CsFile` / `CsDefinition` /
`CsImport` directly — the register functions and Drivers build them.

The Kotlin wrinkle carries over with a sharper edge: **C#'s declaration
kind varies by schema shape** (object → `record`, string enum →
`enum`), and a projection's `toIdentifier` cannot see the schema. The
pattern (worked out in `gen-kotlin`, replayed in `gen-csharp`): one
projection class per kind, each with a constant-kind `toIdentifier`,
all sharing name/export-path derivation, dispatched by ONE shared shape
function. The sharper edge: there is **no catch-all kind** — C# has no
exported type alias (D6), so "everything else" is NON-DECLARABLE: the
transform emits no artifact and ref sites inline the type expression.

## 2. Entity kinds & identifiers

C# output has three entity kinds (`CsEntityKind`), created via the
factories exported by THIS package:

```ts
import { createRecord, createAbstractRecord, createEnum } from '@skmtc/lang-csharp'

createRecord('User')            // → public sealed partial record User { … }
createAbstractRecord('Animal')  // → public abstract partial record Animal;
createEnum('Status')            // → public enum Status { … }
```

- The kind drives ONLY the declaration shell (`toCsKeyword` /
  `CsDefinition`'s dispatch) — like Kotlin and unlike TypeScript, it
  does NOT drive import form: every C# using is namespace-level.
- The D3/D14 modifiers are a property of the KIND, not flags:
  `toCsKeyword('record')` returns `sealed partial record` — `sealed`
  by default, `partial` always (the idiomatic consumer extension seam:
  hand-written members live in a non-generated file of the same
  `partial` type) — and `toCsKeyword('abstract-record')` returns
  `abstract partial record` (the polymorphic parent is open by
  definition; a distinct kind, not a toggle).
- Deliberately NO alias kind (C# has no exported type alias — `using
  X = …` is file-scoped) and NO `val`-analog kind: C#'s distinctive
  constraint is *types only at namespace scope*. `toCsKeyword` throwing
  on `typealias` / `val` / anything else IS that constraint's test.
- Visibility: C# types default to `internal`, so BOTH `exported` states
  render a keyword — `public ` when exported, `internal ` when not.
  This is the **fifth distinct `exported` behavior** across the
  languages (TS `export`, Go casing, Rust `pub`, Kotlin
  nothing-or-`private`, C# `public`/`internal`).
- Deferred kinds (`class` / `interface` at CS-C) arrive with the
  milestones that need them; `toCsKeyword` throwing on them is the
  desired behavior until then.

## 3. The import model of emitted C#

Generators register imports in the concise form; the register function
converts them to `CsImport`s at the register boundary:

```ts
this.register({
  imports: {
    'System.Text.Json': ['JsonElement'],                       // dotted namespace
    'Acme.Shared': [{ name: 'Task', alias: 'AcmeTask' }]       // alias-using
  }
})
```

Rendering rules `CsFile` / `CsImport` apply (authors never hand-write
these):

- **Symbol-level in, namespace-level out (D8).** The symbol names exist
  at the register boundary for dedup bookkeeping and alias support;
  rendering collapses every plain specifier of a module to ONE
  `using <namespace>;`. An aliased specifier renders the per-symbol
  form `using AcmeTask = Acme.Shared.Task;` — the manual seam for
  cross-namespace name collisions (a documented limit of
  namespace-level usings).
- **Two module-key forms**: a dotted namespace (BCL / external
  libraries) or an `@/`-export-path (project files — what the Driver
  passes for cross-file peer imports). Path-form modules resolve to
  their namespace via `toNamespaceName` at render time.
- **The export path encodes the namespace.** The segments after `@/`
  ARE the namespace parts: `@/Acme/Api/Models/User.generated.cs` →
  `namespace Acme.Api.Models;` (file-scoped, C# 10).
  `client.json#settings.basePath` points at the consumer's project
  source root, so files land on the folder-=-namespace convention .NET
  analyzers expect. `CsFile` derives its own directive; nobody computes
  it by hand.
- **Same-namespace suppression**: an import whose resolved namespace
  equals the file's own namespace is omitted at render — C# needs no
  using for same-namespace symbols. The Driver's peer imports vanish
  when peers share the namespace (the common single-`baseNamespace`
  case). A module resolving to the GLOBAL namespace also renders
  nothing — unlike Kotlin's default package (which cannot be imported
  from, so KtImport throws), global-namespace types are visible
  everywhere; suppression is correct, not an error.
- **Sorted, prefix-first** — not style (the consumer's formatter owns
  style) but registration-order independence for byte-identical gates.
  The sort key strips the trailing `;` so a namespace sorts before its
  descendants (`using System.Text.Json;` before
  `using System.Text.Json.Serialization;` — ordinally `;` > `.` would
  reverse them).
- **All usings explicit** — no reliance on the consumer's
  `ImplicitUsings`.
- **No re-exports, no glob imports**: the concise vocabulary has no
  `reExports` field (compile-time absence); `toNamespaceName` throws on
  path segments that cannot be namespace parts (`@/my-models/User.cs`)
  — loud beats `@`-escaped namespace names.

## 4. Syntax helpers

Construct-level helpers for C# syntax — all `Stringable`-compatible:

| Helper | Renders |
|---|---|
| `CsPropertyList` / `CsPropertyArgs` | Record property members: `    [JsonPropertyName("user_id")]\n    public required string UserId { get; init; }` — attribute lines above each property, blank-line-joined, statement-shaped (the D3 nominal-record geometry; contrast Kotlin's comma-joined constructor parameters). Every property is `public` `{ get; init; }`; no `= null` defaults (null already is the default, D4) |
| `CsAttribute` | `[JsonExtensionData]` / `[JsonPropertyName("user_id")]` / `[JsonIgnore(Condition = JsonIgnoreCondition.WhenWritingNull)]` — grammar only; args pre-quoted/pre-built by the caller; which attribute is generator policy |
| `CsAttributed` / `isCsAttributed` | The value-carried class-level-attribute protocol `CsDefinition` reads (one attribute per line above the shell) |
| `CsDocumented` / `isCsDocumented` | The value-carried XML-doc protocol `CsDefinition` reads (`/// <summary>` block above the attributes — C#'s conventional order: doc comment, attributes, declaration); mirror it on the projection — the Driver wraps the projection, not the value |
| `CsBased` / `isCsBased` | The value-carried base-type protocol (` : Animal` after the record name) — declared at CS-A, rendered at CS-B |
| `toCsEnumMemberName(s)` | PascalCase enum member naming + full-set dedup + CS0542 `reserved` pre-seed |
| `withDescription` | XML-doc `<summary>` block above a declaration, XML-escaped (`&amp;` / `&lt;` / `&gt;`) in lang |

The schema→type mapping (`string`, `long`, `IReadOnlyList<…>`,
`IReadOnlyDictionary<string, …>`, `Guid` / `DateTimeOffset` /
`DateOnly` / `TimeOnly`, `JsonElement`) is **generator** territory — it
lives in `gen-csharp`'s value layer, not here.

## 5. Naming & sanitization

- **`sanitizePropertyName(name)`** — makes a name safe as a C#
  declaration name. Plain identifier and not a reserved keyword →
  as-is; reserved keyword (`class`, `object`, …) → `@`-prefixed
  (`@class`, the verbatim-identifier escape — C#'s backtick analog); a
  digit-leading but otherwise identifier-shaped name (`1st`) →
  `_`-prefixed (`_1st` — unlike `@` this IS a rename, so the generator
  pairs it with the rename attribute); anything else (spaces, dots,
  dashes, non-ASCII) → **throws** (rename gen-side before registering).
  Returns a plain `string` — C# has no quoted-property fallback.
- **Renames are attributes, not escapes.** C# cannot quote property
  names, so wire-name mismatches need `[JsonPropertyName]` (or the
  Newtonsoft equivalent) — that policy belongs to the generator. The
  two mechanisms compose: an `@`-escaped keyword still *equals* its
  wire name (the `@` is not part of the name), so it needs no
  attribute. In practice the `@` branch is nearly unreachable through
  gen-csharp: C# keywords are all lowercase and generated properties
  are PascalCased.
- **Contextual keywords are fine**: `record`, `init`, `required`,
  `partial`, `value`, `var`, `async` are legal identifiers — only the
  pinned 77-keyword reserved set escapes.
- **CS0542 is a naming rule the generator owns**: a member may not
  share its enclosing type's name. gen-csharp renames the property
  deterministically (`Error` → `ErrorValue`, attribute keeps the wire
  name) and pre-seeds enum member dedup with the enum's type name
  (`toCsEnumMemberNames(values, { reserved: [typeName] })`).
- **Casing convention**: PascalCase types AND properties, PascalCase
  enum members (the casing itself is applied gen-side via `camelCase` /
  `capitalize` from core; the lang only guarantees the result parses).
- **File extensions**: `.cs`, with the engine-side `.generated.` infix
  (`User.generated.cs`). One type per file — the .NET convention; the
  file name matches the contained type.
- **Path segments are names too**: `toNamespaceName` validates every
  directory segment as a namespace part and throws otherwise.

## 6. C#-output anti-patterns

- **Dropping either line of the header pair** — `// <auto-generated/>`
  without `#nullable enable` is not a style miss, it is a COMPILE
  ERROR for any generated file using `?`: the auto-generated marker
  removes the file from the project's nullable context, and the
  compiler then rejects nullable annotations with CS8669
  ("Auto-generated code requires an explicit '#nullable' directive in
  source") — scratch-proved in the arc spec. `CsFile` always renders
  both; never hand-build file headers.
- **Registering a re-export** — won't compile: `CsRegisterArgs` has no
  `reExports` field. C# has no re-export construct; restructure
  instead.
- **Baking the declaration into the value** — `toString()` returning
  `public sealed partial record Foo { … }` or `[JsonConverter(…)]`
  ahead of it. The Driver + `CsDefinition` add the XML-doc block (via
  `CsDocumented`), attributes (via `CsAttributed`), visibility, the
  keyword chain, the name, and the shell. Return only the body (the
  property list / enum members).
- **Adding `?` twice** — the type expression is the single owner of
  nullability; the property layer's `nullable` arg exists for plain
  string types, never on top of a value that already applies modifiers.
- **Hand-computing the `namespace` directive** — it is derived from the
  export path by `CsFile`. To change a namespace, change
  `toExportPath`.
- **Emitting an anonymous object/enum shape** — C# has none. Synthesize
  a named type (`findDefinition` + `defineAndRegister`) and reference
  it; `gen-csharp`'s `CsObjectValue` / `CsString` are the worked
  pattern — synthesized types land in their OWN canonical file (one
  type per file; a same-file sibling reached from two files would
  duplicate the type in one namespace).
- **Emitting a `typealias` workaround** — there is no alias kind, by
  design (D6). A non-declarable schema is inlined at ref sites, not
  aliased; a generator wanting an alias kind is fighting the language.
- **Naming `System.Text.Json` inside lang-csharp** — the grammar/policy
  boundary in one rule. The lang package renders attributes it is
  handed; serialization flavor lives in the generator (that's the seam
  a Newtonsoft sibling generator replaces).
- **Constructing `CsFile` / `CsImport` / `CsDefinition` in a
  generator** — those are built by this package's register functions
  and the engine's Drivers. Generators speak `register` /
  `insertModel` / `defineAndRegister`.
- **Running a formatter over the output** — render is unformatted by
  design; member spacing and using order are the consumer's
  `dotnet format`'s job (the render sorts usings for determinism, not
  style).

  Snippets, `register` / `registerInto` semantics, cross-generator
