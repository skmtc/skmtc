## 3. Keep

- Mutation-proof every rule's test (break the line, see the named test fail, restore it). It caught nothing false and made the review fast. It is in the step prompt; keep it.
- A narrowed argument type (`DeployRoot`) instead of `as unknown as SkmtcRoot` in tests. Write it into `deno/cli/CLAUDE.md` under TypeScript.
- The reviewer checked claims against skmtc-hub source line numbers. Keep this in the reviewer rules for any CLI ↔ hub contract.

## 4. Deferred

- `deno/cli/lib/deploy-headless.ts` `uploadVersion`: the multipart upload has no `AbortSignal.timeout`, so a stalled hub hangs `skmtc deploy` in CI forever (https://github.com/skmtc/skmtc/pull/268#issuecomment-6542541597).
- `deno/cli/components/DeployView.tsx`: the interactive Ink path never sets `Deno.exitCode`. A TTY user scripting `skmtc deploy && …` gets exit 0 on a failed deploy (same comment).
- `deploy-headless.ts` `toDeployedLines`: the rerun advice after `deploy: error` omits `--env`, because the deployed result does not carry the env flag. Users of `--env staging` will meet it (review thread r4431482829).
- `deploy-headless.ts` `isVersionStored`: a 401 or 403 on the version check still proceeds to pin `@skmtc/server` and run `deno install` before the upload fails. A user with a bad token is left with local `deno.json`/`deno.lock` changes (self-review, kept per the ticket).
- `deploy-headless.ts` `deployVersion`: a 401 gets the `write:releases` scope hint, not "sign in again". A user with an expired token is misdirected (self-review, kept per the ticket).
- `deno/cli/lib/dependency-age.ts` and ~74 other files on main fail `oxfmt --check`. Anyone who runs `pnpm format:check` sees unrelated failures.
- Removing the `publish` alias in a later release, and the skmtc-hub vocabulary change (skmtc/skmtc-hub#2354), are separate issues, as the ticket says.
