## 3. Keep

- **Self-review checks claims against the code:** each new sentence about parser behavior was checked against `toSchemasV3.ts` and `toV3Document.ts` before it was kept, and the review was run on the prose itself. This belongs in `docs/skills/docs-writing` under reference pages.
- **Mutation proof of a grep check:** run the done-when grep against `git show HEAD~N:` versions to show it catches the old text, without touching the tree.

## 4. Deferred

- `deno/convert/deno.json`: still imports `@skmtc/openapi-down-convert`, which no convert module uses. Each down-convert release cascades a needless convert patch release. Anyone releasing meets it.
- `deno/docs/skills/skmtc-architecture/SKILL.md` package graph: the `@skmtc/convert ▲ @skmtc/core` arrow says core depends on convert; it does not. Agents planning release or bundle work from the skill meet it.
- `deno/docs/reference/settings/source-resolution.md`: the Swagger 2 error text "failed to convert Swagger 2 to OAS 3.0" and the HTTP status table are unverified against `cli/`. Users debugging a failed fetch or a failed conversion meet it.
- `deno/docs/reference/error-codes.md` MISSING_OBJECT_TYPE: it says "the 3.1 parser is silent"; the 3.2 parser is silent too. 3.2 users reading the page meet the gap.
- `deno/docs/friction-log/` entries still describe the 3.1 → 3.0 down-convert and "expected 3.0.x or 3.1.x". They are dated records and were left by design.
- `deno/docs/skills/skmtc-architecture/SKILL.md` third-party table: it lists npm `swagger2openapi`; convert now uses the in-repo `@skmtc/swagger2openapi` port.
